## Research Question

用户说“帮我分析一下最近状态”，首先授权的是**协助理解问题、提出有限解释或建议**。这句话没有唯一确定“状态”、时间范围、数据来源、云端发送范围，更没有授权写入。即使已经配置 Provider，也不能把请求自动解释为全库读取或发送。

更具体的“线代现在学到哪里”可合理预期为本次核对该科目章节状态；“只在本机找上个月写过午后困的日记”可支持限定正文匹配，却明确排除向 Provider 披露命中信息。差异来自用户可理解的任务对象与处理去向，而不是材料是否对模型有用。

## Access vs Disclosure Model

### Local Access

表示 MindDiary 可信本地代码为当前用户目的读取、匹配或计算数据。SQL 对正文做条件匹配、先加载完整对象再删字段、从附件提取文本，都算访问相应内容；不以最终返回字段决定访问范围。

本模型约束的是**为 AI 辅助任务而获取与使用本地材料**。用户在普通编辑器打开日记、自己使用搜索或备份，是各自本地操作目的，不因此把材料交给 AI；“不要让 AI 看日记”也不自动等于禁用用户自己的日记界面或删除日记。

请求本身足以支持合理预期的本地访问，需同时满足：对象/任务直接明确，字段与日期范围可从请求理解，访问是完成该事实请求的自然部分，没有相反拒绝，并且当前能力能遵守范围。已有有效材料足够时仍不新增读取。此为低摩擦的语义依据，不是绕过敏感边界的自动许可。

### Provider Disclosure

表示原文、标题、统计、命中结果、摘要或其他可推知源信息的内容进入当前配置的 AI Provider 请求。出站以**实际材料及其来源**判定，而不是以字段叫 summary、metadata 或 safe 判定。

Local readable ≠ Provider disclosable。允许本地匹配日记，不自动允许发命中日期：日期与关键词组合也可能揭示经历。可成立的路径是先在本机定位，由用户明确选定允许发送的日期/短片段；也可全部留在本机，只显示本地结果。此例是研究路径，不宣称当前通用助手已支持。

用户在已清楚表示“发送给当前 Provider”的上下文中主动提交一段文字/独立页，可构成对本次限定材料的披露意图，无须为了证明安全人为增加额外确认仪式。但“可以看这页”若没有明确本机或外部处理含义，只能确定材料范围，不能推定云端发送。设置 API Key 表达启用服务，不表达披露全库。

每次实际出站都需在语义上仍符合允许范围，包括追问、重试、重新生成和摘要；不决定是否每次都弹窗。Provider 目标改变不能静默沿用针对旧目标的披露理解，至少重新让用户理解去向，不在本文规定操作方式。

### Derived Material

允许产生摘要不等于允许保存为长期画像、跨目的使用或再次发送。派生材料的本地使用与 Provider 披露都继承来源限制，并可能因组合/推断更加敏感。它不是授权来源，也不因删掉原文而变成独立证据。

### Action Authority

看数据、发数据、生成候选，与应用候选/执行写操作是独立权力。保持既有链：**candidate → local validation → review → explicit confirmation → trusted idempotent execution**。模型不直接读写 SQLite；写入成功来自可信执行结果，而不是模型说“已安排”。

禁止后台自主写入；不改变既有回执、确认、失效检查和恢复边界。隐藏模型推理不请求、不持久化；不假定 Provider 具有可依赖或可撤销的持久记忆。

## Data Boundary Matrix

下表的“默认假设”是研究起点，不是已生效的访问表。各类可重叠：科目名兼具学习状态和用户内容；标题不因短而失去隐私。用户应能知道实际处理类别、对象/日期范围、去向与限制，不必被迫阅读完整字段清单。

| Data / 类别 | Local access expectation | Provider disclosure expectation | User visibility expectation | Default assumption / typical escalation | Derived-use concern |
| --- | --- | --- | --- | --- | --- |
| Task metadata：状态、计划日、估时、关联；运行与学习状态 | 明确安排/负荷/任务查询下的相关集合通常显然 | 仅任务目的所需状态/预算片段，不自动发所有关联 | 哪天、哪些任务、当前状态及估时口径 | 限定日期/科目；跨期或展开关联需新依据 | 负荷统计仍是个人状态，撤回后旧统计不能绕过 |
| Task title / description；用户内容 | 标题用于辨认当前任务可预期；description 不总是需要 | 标题也须在明确披露范围；不顺带全文描述 | 是否包含用户写的文字 | 未必需要 description；诊断具体内容时再说明 | 旧候选引用标题也继承限制 |
| Subjects；个人学习目标 | “线代”身份定位合理，不需全科目 | 必要名称/进度，不是所有目标 | 哪个科目，是否同名已确认 | 单科；跨科比较另定范围 | 名称可暴露考试/职业方向 |
| Chapter titles/status；内容与进度 | 进度问题中有序章节及标记合理 | 仅所需标题/状态，不附笔记 | 记录标记，不是实际理解结论 | 不扩章节正文/笔记；必要时单独说明 | 章节摘要不能证明掌握；撤回不靠缓存重述 |
| Mistake metadata；个人薄弱点与调度 | 到期安排/专题概况的限定记录 | 需要解释的数量/日期/状态也要允许 | 到期/收录/调度计数的含义 | 不因 metadata 就全库可用 | 计数与主题组合可能敏感 |
| Mistake question；题面内容 | 找专题/看此题时的限定题面可预期 | 题面节选与题目图是不同范围；均需明确去向 | 发的是文字还是图、哪道题 | 不展开答案/笔记/图像；缺题面再补 | 主题标签/诊断继承题面范围 |
| Mistake notes；私人学习反思 | 非显然；只有指定错误步骤/笔记时成立 | 另明示所选片段，不由题面许可推导 | 是否为本人步骤、截取范围 | 通常排除；分析该错误步骤才提出 | 笔记形成的个人原因推断同样受限 |
| Mistake answer；答案/可能的本人作答 | 非显然，题面请求不涵盖答案 | 指定对照才可发送对应片段 | 是标准答案还是用户作答、是否含图 | 通常排除；必要对照单独定范围 | 由答案生成的诊断不能在答案撤回后偷偷保留为依据 |
| Focus timestamps；活动时刻 | 问某段时刻才可能需要；投入总量不需全部时刻 | 不从允许总量推导允许时刻序列 | 日期/时刻、关联对象 | 优先最小必要口径；细到时刻需说明用途 | 作息、活动规律推断可比单条更敏感 |
| Focus aggregate；个人投入统计 | 明确投入比较/执行复盘可预期 | 仍需对象、日期及披露含义明确 | 合计/分科目、分钟/次数、覆盖 | 聚合非自动放行；细分或跨期重判 | 小样本可近似原记录；来源限制不消失 |
| Countdown；目标/期限 | 请求期限安排时可预期 | 必要目标和日期，而非所有倒计时 | 用户配置的目标，不是官方事实 | 无期限问题通常不取 | 目标摘要可透露人生计划 |
| Diary existence/date；反思记录轨迹 | 明确定位/覆盖时有限可预期 | 不是无敏感的“仅日期”；主题命中还透露经历 | 是否只查存在，是否正文匹配产生日期 | 泛化状态问题不默认使用；宽泛拒绝日记时排除 | 命中数量/日期也是来源派生信息 |
| Diary title；私人反思文字 | 即使无正文也属内容访问 | 不能借 metadata 默认发送 | 明确是标题文字 | 非显然、通常排除；用户选定定位材料时限定 | 标题改写/概括仍受限制 |
| Mood；反思状态 | 敏感；问学习效率不自动授权 | 须明确用户愿意分享此状态 | 原记录还是模型推断 | 通常排除；不替代已拒日记 | 情绪趋势/标签可能更敏感 |
| Diary body / excerpts；敏感反思 | 指定正文检索/选区才成立；本地匹配也计入 | 明确所选原文片段与去向；本地许可不够 | 篇/日期/片段，原文而非安全概括 | 不默认；拒绝后不重复索要 | 摘录、摘要、情绪与旧建议继承 |
| Planning history；建议与决定记录 | 用户问上次安排时有限可预期；不等于长期记忆 | 仅选定历史片段/允许反馈，不全量发送 | 历史候选与当前结果分开，哪些类别纳入 | 当前问题不自动调用；参考旧计划需说明 | 候选文字可能携带日记/笔记事实；审计留存不等于证据复用 |
| Model-derived summary；模型解释/压缩材料 | 来源、目的、有效性和允许范围均需成立 | 按仍允许的来源约束，不能自动安全化 | 模型生成、哪些来源、限制与可用性 | 无来源或混合来源无法分离时不作证据 | 撤回来源后不得作事实、提示词或检索线索 |
| Attachments：text/image/PDF；外部文件内容 | 用户指定材料的读取可预期；一页不授权全文件内容 | 单独理解发文本提取还是图像，以及页面范围 | 文件/页/裁剪/提取失败与目标 Provider | 只处理提供的范围；能力不支持时用独立页/手打文本 | 提取文本、图像描述、诊断都继承范围 |
| Attachment metadata；文件身份 | 为用户选文件/辨认材料读取必要属性合理 | 名称/MIME/大小也是发送内容，不自动全发 | 文件名可能含姓名/学校；元数据与内容分开 | 必要展示不等于向模型发送；多余信息可不纳入 | 文件名派生标签不应成为隐性个人资料 |
| Local absolute path；设备/身份信息 | 可信本地文件定位可能需要 | 本研究学习场景无发送必要；不作为模型上下文 | 可用文件名或用户可辨认对象说明，不暴露绝对路径 | 排除出站；诊断需求不属于本次学习场景 | 错误信息/摘要里复制路径仍是泄露 |
| API credentials；Secrets | 仅可信 Electron main 为鉴权使用 | 不进入模型 messages、附件、总结或证据；鉴权头用途独立 | 用户理解已配置哪个服务，无需看到明文 | 不是可向模型升级开放的数据类别 | mask/present 也不是学习证据；备份脱敏不授权披露其他数据 |

## Scope Model

范围同时受对象、时间、字段、目的、会话及披露目标约束；任一维度扩大均不能由另一维度的许可替代。记录之间有关联，只说明能定位，不说明可沿关联访问。

### Object Scope

一个任务、一个科目、一道题、一篇日记、一个附件须可辨认。“这页草稿”不扩成整个 PDF；“这道题”不扩成同科所有题；同一天或同主题不是授权继承关系。用户点选材料可清楚表达对象，但不能单独说明云端处理去向。

### Time Scope

今天、最近七天、上个月须与本地日期及用户理解对齐；“最近”含糊时不能静默选全历史。篇数上限不是时间范围。进入新日期、追加比较时段时重新判断范围；不在本文设统一过期分钟数。

### Field Scope

metadata、title、question、notes、body、answer、image/extracted text 分开。许可约束内部匹配与本地加载，也约束输出。若现有函数返回完整对象、内部匹配被排除字段，不能先调用再删字段来满足“只读题面”。需承认当前能力不适配，采用已允许材料或有限帮助，不在本文实现替代查询。

技术上为呈现指定页可能涉及文件容器处理，不能以此偷换成允许提取/分析其他页内容；当前 PDF 路径确实遍历各页，因此不能声称满足指定页访问。本文不设计分页解析机制。

### Purpose Scope

用于回答“最近数学投入有没有增加”，不自动用于判断心理状态、训练个人画像、未来规划或导出分享。来源得到本地许可，也不使任意派生用途成立。使用派生统计继续回答同一个比较问题，仍须符合披露范围。

### Session Scope

“这次分析可以”不能解释成整个会话以后任意问题均可使用，更不能跨会话长期复用。同一目的、同一范围、无撤回的紧邻追问可能无需重新打断用户，但仍要判断材料是否相关且允许；新目的/新对象/新日期/新 Provider 不能借“还在同一聊天”扩权。

本次不选择持久期限、授权保存方式或 session grant。已有明确拒绝不能因下一轮消息、移除后重新加入 Context、重试、跨日或重开页面而被当作新的同意。后续若用户明确改变边界，只按新的具体范围恢复，不恢复其他类别。

## Contextual User Expectations

Obvious access 是请求自然指向的对象与字段，如“线代进度”中的该科章节标记；non-obvious access 是虽然相关，却不是普通理解下完成请求的自然部分，如为了安排两小时查旧规划成效；sensitive access 是私人反思、答案、附件等容易超出分享预期的处理。三者可重叠，不映射成三档 UI 权限。

**Example A：“看看我最近为什么学习效率下降。”**

| 材料 | 与请求的关系 | 研究判断 |
| --- | --- | --- |
| 当前自述、效率含义、比较时段 | 定义问题必需；未必需任何记录 | 先澄清；不能把泛化问题当取全库权限 |
| Tasks / focus | 若要核对记录层面的负荷/投入，是可合理预期的限定数据 | 比较口径与时间明确后，可支持有限本地访问；原始时刻/描述不因总量有用而全部开放；云端去向另说明 |
| Diary title | 不是完成记录对比必需 | 非显然的私人文字；不能因“标题而已”纳入 |
| Diary body / mood | 可能帮助理解某段自述，但相关性不产生权力 | 需额外用户意识与限定选择；拒绝后继续有限分析，不以“想知道原因就必须允许”施压 |
| Attachments | 没有指定文件与内容缺口时超出预期 | 默认不访问，也不沿任务/日记关联加载 |

**Example B：“帮我看看这道题，我可以给你看这页草稿。”** 只确定了本题/指定页内容供检查的意图；若已清楚是在发给 Provider 的入口发送，则支持该页的限定披露。整 PDF、错题本答案/笔记、同日日记、相似题历史均不随之开放；关键行不足时问这几行，而不是扩读。

**Example C：“不要看我的日记。”** 按宽泛拒绝理解为本次及后续相关 AI 使用中不访问/披露/依赖日记正文、节选、标题、心情、存在轨迹以及由它们生成的摘要或情绪推断；无需让用户逐字段列黑名单。不妨碍用户自己在本地看日记。“正文别发给 Provider，但本机可以找”则是更窄的撤回，保留明确许可的本地搜索，不自动许可发匹配日期或摘要。

这些规则允许低摩擦显然访问，同时承认预期不是读心术：用户已有明确限制优先于推测；模型或材料里的“可以访问”不能替用户扩大权力。

## Search Access Semantics

**Internal Match Surface 也是访问范围。** “只返回三条”控制输出量，不能说明只访问三条或只读 metadata。正文匹配但只返回日期，仍读了正文；答案关键词匹配产生一个布尔命中，也使用了答案。

| 用户意图 | 可支持的匹配范围 | 不能偷换的边界 |
| --- | --- | --- |
| “找一下行列式相关错题” | 范围明确后优先仅题面；题面能满足就没有理由默认用 answer/notes | 用户没有授权所有文本字段；现有错题搜索 `question OR answer OR notes` 不能充当 question-only 能力 |
| “在我这道题的笔记里找当时写的步骤” | 指定题 notes 的必要匹配 | 不扩到所有答案、图片或同题历史；笔记授权不等于 Provider 发送 |
| “找上个月写过午后困的日记” | 用户知道关键词需在上个月正文中本地匹配后，限定正文访问可成立 | 需说明正文匹配而非只搜标题；当前 `searchEntries` 没有日期参数，不能先全库搜再过滤假装只读上个月 |
| “只在标题里找” | 标题匹配 | 当前日记搜索含正文，不能直接拿来满足此限制 |
| “只在本机找，不要发出去” | 已允许范围的本地搜索、结果本地展示 | 匹配日期/命中数/短摘录均不能自动向 Provider 发送 |

当前日记搜索还返回正文前 200 字符片段、标题和心情，并非仅日期；错题搜索返回完整行。结果裁剪不是访问权限隔离。现有能力无法遵守时，明确限制，用户可自己选择并提供独立片段；不能把“去本地搜索”建议变成助手自动执行被拒访问。对用户自己的搜索界面也应如实说明现有匹配范围，不能把它推荐成尚不存在的严格字段/日期隔离能力。

搜索结果本身也可能是敏感派生信息，例如“该日记命中失眠”。未经允许，不把命中标签、日期列表或数量作为发送原文的隐蔽替代。

## Derived Material Rules

**派生材料不能自行取得比来源更宽的使用权。** 缩短、聚合、脱去姓名、把原文改成情绪标签或模型结论，均不自动降敏或清除来源限制。统计可能减少暴露，但粒度、样本、组合和目的决定实际风险；不按 aggregate 标签一律放行。

| 来源 → 派生材料 | 来源被拒绝/撤回后的语义 |
| --- | --- |
| Diary body → AI summary / sentiment / 旧建议 | 不再引用源事实，不继续影响当前解释/建议排序，也不把摘要当 future retrieval hint；允许保留的历史显示另论 |
| Mistake answer → AI diagnosis | 不拿旧诊断假装只看题面得出。已有用户步骤可独立支持的结论，应重新基于这些允许材料得出并标明范围 |
| Attachment → extracted text / 图像描述 | 提取文本不是新授权文件；页、字段、用途和披露限制继续适用 |
| Focus records → aggregate | 全面撤回来源使用则旧 aggregate 也停止证据复用；仅拒绝发送原始时刻、明确允许指定周合计时，该合计可在限定范围披露 |
| Planning history → model summary | 摘要不是长期记忆权力；其中旧候选事实、日记派生判断及当前状态必须分别满足范围，不以摘要替代失效来源 |
| 多来源 → 混合总结/当前会话草案 | 能清楚分离且独立支持的允许部分才可继续；无法分清就不把混合材料当证据或重新发送，改用其余材料形成有限回答 |

上述 focus 分支不是“派生比来源权力更大”的例外：用户明确允许本地读取来计算，同时只许可合计出站，是从一开始就限定了不同处理方式。不能在用户已说“不要再用 focus”后自行套用。用户后来独立自述同一事实，可作为新的用户陈述，但必须确实由用户提供，不能用诱导问题把撤回摘要洗成新授权。

旧建议可作为“过去曾显示过这段文字”的历史对象；若用户仅要求改文字，仍须排除被撤回事实及其隐性影响。不能保留日记导致的优先级，再声称没有引用日记。内容可独立成立的普通方法不需要追溯禁止一切同类知识，但须由当前允许材料/通用知识重新支持，不能靠旧私人诊断定位它。

已经由用户确认创建的任务仍是 SQLite 中的实际本地记录，撤回日记不自动删除任务或回执，也不回滚过去动作。但若任务标题/描述复制了被撤回事实，不能仅因“已成为任务”就免除这部分披露限制。独立的任务状态只有在任务访问目的仍允许且不绕过来源拒绝时才可用。来源撤回与数据删除、任务取消是不同用户意图。

## Revocation Model

先辨认撤回对象：本地新增访问、Provider 披露、派生使用、动作确认可以分别撤回；“不要再用我的日记”按整体使用拒绝处理，“可以本地看但别发”保留本地限定用途。不明之处先停止可能越界的使用，继续无关的已授权帮助，不以等待澄清为理由照常发送。

| 阶段 | 应停止/允许什么 | 用户可得到的真实说明 | 不可承诺 |
| --- | --- | --- | --- |
| Before access | 不发起被撤回访问，也不先搜索后丢弃；可用其他允许材料 | “接下来不读取这类材料，按你提供的信息继续。” | 未实际检查就宣称历史上从未读过 |
| After local access | 本地已读不能倒转；若撤回来源使用，不再复用原对象/摘录/统计；若仅撤回披露，可保留被明确允许的本地用途 | 分清已本地读取与尚未发送；不重复暴露内容来证明撤回 | “内存/备份/历史都已彻底删除”——本次没有删除系统 |
| Before provider send | 以实际发送时仍有效范围为准；已构建请求/缓存快照不能绕过撤回；排除受影响内容及派生物后才可继续允许部分 | “已准备，但这部分不再发送。”仅在确知未发送时如此表述 | 以点击生成时曾同意为理由继续发 |
| Send underway / status uncertain | 停止后续发送和复用；对受影响的晚到结果不采纳为新证据/可应用候选 | 无法确认是否已被接收时说“可能已经发送”，不能报未发送 | 取消/超时就代表 Provider 未收到或已删除 |
| After provider send | 无法收回已发送字节；未来请求排除原文、旧回答里的源事实、摘要和重试快照；如需继续，基于剩余允许材料重新回答 | 明确哪些类曾发送、之后不再纳入什么；原结论若依赖撤回源，停止把它作为当前有效依据 | Provider 已忘记、已从日志/训练数据删除，或能保证不再内部影响 |
| After derived material exists | 按用途区分历史显示、证据使用、出站和检索提示；混合来源不明时停止受影响材料复用 | “旧回答仍可能在历史里，但不再作为后续依据。”该能力未实现前不能宣称已完成 | 只藏原文却继续用摘要；只加一句“忽略日记”但仍发送旧材料 |
| After action confirmed/executed | 撤回数据不等于取消已执行动作；尚未执行且依赖失效来源的候选不能照旧推进，应重新验证/审阅；另行取消具体动作按现有边界处理 | 区分建议、已确认、执行中/不确定、已创建 | 未核实就声称写入被取消或已回滚 |

### 历史保留与未来使用是不同用途

| 用途 | 来源撤回后的结论 |
| --- | --- |
| 本地保留历史记录 | 撤回使用本身不自动要求删除，不改变 Planning History 既有保留/回执契约；若用户明确要删除，是另一个范围，不声称已处理 |
| UI 可见旧回答 | 可在用户保留历史的前提下作为过去对话显示，并让用户知道不是仍有效依据；不自动改写历史掩盖曾披露事实 |
| 当前推理证据/建议依据 | 不可继续使用受影响原文、摘要、统计、情绪或旧诊断；无需获取隐藏推理来验证，约束可观察的输入、引用和输出行为 |
| Future retrieval hint | 不可用被撤回的日期、主题、人物或摘要引导“重新发现”同一私人材料；允许源须有独立且当前成立的定位依据 |
| 下一轮 Provider 历史消息 | 显示在历史中不等于可重新发送；文本里有被撤回事实就不能整段照发；难以分离时不用这段历史 |

当前源码没有提供这一整套来源撤回保证。这里定义的是未来承诺必须达到的语义，不能向当前用户声称输入一句拒绝就已技术上清理所有上下文。也不假定 Provider 保持会话记忆；即使客户端每次独立组装消息，已经发生的外部披露仍是事实。

## Graceful Degradation

拒绝改变可用材料和可支持结论，不应自动终止帮助。降级不承诺同等诊断精度，也不把缺少授权写成数据不存在。

| 被拒范围 | 仍可提供的帮助 | 必须保留的限制 |
| --- | --- | --- |
| Diary（含派生材料） | 用允许的任务/focus 做执行或负荷观察；按当前自述给起步建议 | 不解释心理原因，不以标题、心情、旧摘要替代；不反复求取 |
| Mistake answer | 检查主动给出的实际步骤；给通用验算、自查方法 | 不借搜索答案或旧诊断定位个人错误；无步骤就不能声称找到错误点 |
| Notes 或题面图片 | 用允许的题面文字/数量做有限概况，邀请用户自愿手打关键行 | 不加载关联图片，不把 notes 当 metadata |
| Attachment | 接受用户手打题面/关键行，或给通用检查法 | 不读取文件或提取文本缓存；自愿提供文本仍须理解其发送去向 |
| Provider disclosure，但允许本地访问 | 在真正可本机完成的路径展示本地事实、匹配结果、确定性统计；用户可自选要分享的内容 | 不假称具有本地大模型解释能力；连命中数/聚合也不偷偷发云端 |
| Focus / 结构化记录 | 用用户自报预算、任务清单和困扰生成未核对草案 | 不宣称与数据库安排一致或推断实际投入 |
| All local learning records | 普通 Chat、知识讲解、用户当下自述/主动提供且允许披露的材料 | 清除证据用途上的旧本地来源影响；普通云端 Chat 仍会发送用户消息，不等于离线 |
| 所有 Provider 发送也被拒绝 | 保留普通本地记录、编辑/查看和已有确定性功能；用户自行决策 | 不能调用云端 Chat，也不为“功能可用”假称有离线 AI |

Graceful Degradation Principles：说明还可做什么；用剩余允许材料完成有限目标；仅询问真正会改变结论且用户愿意提供的信息；拒绝后不反复请求同一敏感类别；无能力遵守范围就承认限制；不以 Allow All / Cancel 作为唯一产品语义。

## Authorization vs Confirmation

| 用户表达/行为 | 可以表达的同意 | 不能替代 |
| --- | --- | --- |
| “看看线代进度” | 本次限定本地事实查询的合理预期 | 发送全部科目、创建学习任务 |
| “可在本机搜这几篇日记” | 本地指定范围匹配 | 命中原文/日期/摘要发给 Provider |
| 明确目的和去向后“把这段发给当前 Provider” | 限定 disclosure | 未来跨目的使用、读取关联材料、执行动作 |
| “帮我安排” / “给个建议” | 生成可审阅的候选 | 保存、改期、完成、删除任务 |
| 审阅具体候选后明确“创建这两项到明天” | 对明确对象、日期和变更的确认意图 | 跳过本地校验、失效检查、可信执行与幂等边界 |
| 润色后点击应用 | 对当前有效选区及候选的应用 | 改其他段落、让模型直接写 SQLite |
| 单独“可以” | 仅结合紧邻且唯一明确的确认对象解释 | 从“可以看”跳到“可以写”；一次含糊答复同时批准多个权力 |

若上一句同时询问看数据与创建任务，“可以”不足以分清两种权力，应澄清具体动作，不用模型推断补齐确认。自然语言表达这里仅用于研究语义，不新增聊天写入机制；仍通过已有候选审阅与显式确认执行。

## Scenario Access Paths

沿用 D0.1 编号，不重写原场景。下面的 Provider-disclosable by default 指**请求本身是否足以支持该披露理解的研究判断**，不是已实现默认配置。若已有清楚且仍有效的处理去向说明和限定同意，可沿其范围继续，无需人为加一道重复确认。

### Scenario 1 — 两小时安排

- User intent：在剩余 120 分钟、低精力条件下安排下一步。
- Reasonably expected local access：确需核对时，相关今日任务/估时、科目章节及到期关联概况；已有自述足够则不新读。
- Non-obvious local access：日记存在/正文、focus 历史、旧规划、到期题答案；固定 Today Action 读过这些对象不代表聊天请求也授权。
- Provider-disclosable by default? 不由“安排”本身推定；在已理解云端分析范围时，可发送限定任务/章节/到期概况；必要题面短片段需让用户知道，答案/日记不纳入。
- Needs additional user awareness? 哪些已有安排仍占剩余时间、发哪些记录，而不是把今日总预算当剩余预算。
- If denied：按用户清单和科目概况给未核对草案；拒绝题面不妨碍粗粒度顺序。
- Derived material rule：旧规划携带已撤回日记推断时，不能保留其优先级理由；用剩余允许事实重述。
- Write authority：仍须独立审阅、确认，不因安排请求创建任务。

### Scenario 2 — 效率下降

- User intent：理解投入与感受不一致，找到可尝试的调整。
- Reasonably expected local access：先确定效率含义和比较期，再取该科任务当前状态/估时、允许的分期 focus 汇总。
- Non-obvious local access：精确时刻、任务长描述、日记标题/心情/正文、附件；不能用相关性替代同意。
- Provider-disclosable by default? 请求不自动许可；限定汇总也需清楚其来源、时期及发送去向。未允许时保留本地观察。
- Needs additional user awareness? 合计仍是个人数据，当前 done 不是当期实际完成事件；反思片段是可选且独立的披露。
- If denied：用结构化记录的有限观察或自述；不知道原因就明确未知。
- Derived material rule：撤回日记后，不用旧情绪摘要为投入变化作解释；只拒绝原始时刻且明确许可合计的范围可继续。
- Write authority：建议调整不修改任务/科目状态。

### Scenario 3 — 线代进度

- User intent：找回软件记录的学习位置。
- Reasonably expected local access：该科目身份、章节标题/顺序/完成标记，通常一次足够。
- Non-obvious local access：其他科目、日记、focus、错题答案均无必要。
- Provider-disclosable by default? 本地事实请求不自动需要外发；若用户清楚要求云端解读，仅必要章节摘要可在限定理解下纳入。
- Needs additional user awareness? 读取哪一科，是否向 Provider 发送标题/标记；本地直接显示可不经过 Provider。
- If denied：按用户给出的章节回答，或让其自行查看科目界面。
- Derived material rule：旧进度摘要不能绕过撤回或当实时状态。
- Write authority：None；不标章节完成。

### Scenario 5 — 历史日记

- User intent：找到以前午后困的具体记录和当时尝试。
- Reasonably expected local access：用户知道是在限定日期正文中匹配后，该范围访问可以成立；单凭“以前是不是这样”尚未指定日记来源。
- Non-obvious local access：全库、邻近日期正文、同日附件、由旧 summary 推回敏感日期。
- Provider-disclosable by default? 否。本地搜索允许而 disclosure denied 是完整有效分支；命中日期也非自动可发。
- Needs additional user awareness? 内部会读正文；当前关键词搜索没有所需日期隔离保证；如只分享片段，应由用户选定可独立处理的材料。
- If denied：按当前回忆讨论方法或用户自己选片段；不做正文匹配，不宣称历史已核实。
- Derived material rule：已撤回的日记摘要不能作证据或搜索提示；旧记录可否显示与继续使用分开。
- Write authority：None；不改日记、不保存新画像。

### Scenario 7 — 专题错题

- User intent：核对行列式相关收录情况，再讨论具体错误。
- Reasonably expected local access：限定日期/科目内的题面匹配及记录 metadata；不能虚构重错次数。
- Non-obvious local access：answer/notes 搜索、答案图和同题全部附件；题面许可不覆盖这些字段。
- Provider-disclosable by default? 仅在已理解云端分析且范围明确时发送相关题面/概况；答案/笔记仍不默认。
- Needs additional user awareness? 当前搜索会匹配答案/笔记，无法伪装 question-only；要分析个人错误还需本人步骤。
- If denied：用主动提供步骤独立验算，或给通用自查；题面概况不能证明个人原因。
- Derived material rule：答案撤回后旧 AI diagnosis 不继续影响判断；不借旧诊断检索私人笔记。
- Write authority：None；不更新掌握/SM-2，不自动建复习任务。

### Scenario 8 — 知识问答

- User intent：解释克拉默法则并举例。
- Reasonably expected local access：无新增本地学习记录；当前问题足够。
- Non-obvious local access：为了个性化读进度、错题或日记。
- Provider-disclosable by default? 清楚的云端 Chat 发送可支持当前用户问题的披露；不附无关本地 Context 或被撤回来源的旧回答。
- Needs additional user awareness? 普通 Chat 会发消息给已配置 Provider，零学习记录读取不等于离线。
- If denied：拒绝所有学习记录仍可正常知识问答；也拒绝出站则不能云端生成。
- Derived material rule：无需本地摘要；历史中含私人学习事实也不因六条预算而自然变得可用。
- Write authority：None。

### Scenario 9 — 明确拒绝日记

- User intent：在不分享日记的前提下获得帮助。
- Reasonably expected local access：主路径无新增读取；仅明确想核对负荷且允许时取任务/focus。
- Non-obvious local access：日记标题、心情、日期轨迹、正文搜索和旧总结，全部不可作为替代入口。
- Provider-disclosable by default? 当下自述可在清楚的云端 Chat 中发送；日记及其派生内容不得继续纳入。
- Needs additional user awareness? 若之前已发过，只说明无法收回既有披露、未来如何排除；不重复展示私密内容。
- If denied：给基于自述的小调整；不反复求权，不诊断人格或心理原因。
- Derived material rule：旧聊天可见不代表可重新发送/引用；当前混合总结无法分离则停止复用。
- Write authority：None；接受建议也不等于确认创建任务。

### Scenario 12 — 指定草稿

- User intent：检查本题这页实际推导。
- Reasonably expected local access：明确的独立页/图片/文本；题面步骤齐全不查其他记录。
- Non-obvious local access：整个多页 PDF、错题本答案/笔记、同日日记、相似题历史。
- Provider-disclosable by default? 仅在用户理解将该页发给当前 Provider 后，对该页限定内容成立；“可以看”本身不确定去向。
- Needs additional user awareness? 图片还是提取文本、发送范围、是否含文件名、视觉能力/提取限制；当前 PDF 全页遍历不能承诺只访问指定页。
- If denied：手打关键行或通用验算方法；答案被拒仍可看已有步骤；无法满足单页范围就不读取整份文件。
- Derived material rule：提取文本/图像描述继承页范围与撤回；不能文件移除后仍用提取缓存发送。
- Write authority：None；分析不改错题记录。

## User-facing Disclosure Requirements

用户至少需要能理解以下事实；本文不指定弹窗、按钮、交互布局、逐次确认或 session grant。

1. **处理地点和目标。** 哪部分只在本机处理，哪部分将发送给当前配置的 AI Provider；配置了服务不等于本地分析，更不等于所有记录可发。目的地变化应重新明确。
2. **数据类别与大致范围。** 哪个对象、日期/篇数/页面、哪些内容字段；正文检索不能只叫“搜索记录”。无需展示原始 SQL 或所有技术字段。
3. **内容形态。** 原文/摘录、模型摘要、确定性统计、图像、文件元数据分别说明；“摘要”不能掩盖直接复制正文。
4. **已发生与计划发生。** 本地已准备、尚未发送、已纳入某次请求、发送状态未知分别表述；不能说 Provider 内部确实采用了某材料。
5. **用途与后续复用。** 本次分析不自动变长期画像；追问或重新生成可能重新出站，旧回答可携带来源事实。
6. **拒绝与撤回后的帮助。** 仍能做什么、哪些结论不再支持；不声称收回已发送字节或删除 Provider 数据。
7. **动作边界。** 生成建议、本地显示和真实写入不同；用户能辨认具体待确认动作与执行结果。

### Existing Context UX — 已表达与未表达

| 当前 wording / 体验 | 已表达的事实 | 可能低估或误解的范围（源码推导，非真人实测） |
| --- | --- | --- |
| Quick Prompt + 可移除 chips | 有哪些类别被附加；可在发送前移除 | 标签没有给出字段/日期/出站形态；不能只凭点过模板认定已充分理解 |
| “心理按摩” → “近期复盘” | 模板会关联反思 Context | 可能误以为只是对话建议/统计；实际最多七篇正文摘录，没有起始日期，不是已生成的安全总结 |
| “今日日记” | 当前 entry 内容参与请求 | 标签不保证 entry 就是今天；实际含标题和正文，不能仅凭名称理解日期/篇目 |
| “错题规律” / “未掌握错题” | 所附类别与掌握筛选 | 实际含题面与笔记摘录，不是只发次数；不会因此发送答案，但本地完整对象已读 |
| “学习概况” | 附入总体学习信息 | 涵盖多科名称/章节、今日任务标题和 focus 合计，不是仅所问科目的进度 |
| Today Action “当前本地预览（仅本地读取）”及请求快照 | 明确预览不请求 AI、不改任务；当前预览与生成时快照分开 | 是可借鉴的事实分离方式，不是通用字段许可或撤回功能 |
| Daily Review “只读取本地安全摘要” / “不会把日记正文…发送给 AI” | 预览与生成阶段分开；所列正文/答案/图片确实不出站 | 前句可能淡化完整对象本地读取；后句不代表标题/心情也不出站，更不代表没有日记使用 |
| Mistake Review 入口 | 明确是 AI 复习规划 | 打开后有可用题即生成；不能把另外两个 planner 的“预览不发送”预期套在此入口 |
| 附件名、大小、PDF 页数 | 用户能确认选择了哪个文件，看到读取状态 | 不证明只处理用户口头指定页；文本提取与图片发送不同，文件名也可能出站 |
| 移除 Context / 重新生成 | 前者改变当前 composer 的类别；后者重发原请求快照 | 移除不等于来源全面撤回；后续正常历史文本也可能含派生内容，不能宣称“不再附 Context 就不再使用” |

不据此断言每项都必须增加 permission dialog。可以参考 Today Action / Daily Review 对本地预览和请求依据的区分，先把用户需要理解的事实讲清；是否改变具体 UI 留待独立决策。

## Cross-scenario Findings

- 可本地搜索 ≠ 可发送命中原文，亦不自动可发送命中日期/统计。
- 允许题面 ≠ 允许答案/笔记/图片；限定返回条数 ≠ 限定内部访问字段。
- 允许这页 ≠ 允许整份文件；文本裁剪 ≠ 页面访问隔离。
- 允许本次分析 ≠ 允许跨目的、跨会话或换 Provider 继续复用。
- 来源撤回后，原文、摘要、聚合和旧建议中的受影响事实都不能自带豁免；保留历史显示 ≠ 继续作证据。
- Aggregate / metadata 不是天然低敏感类别；组合后可能更容易暴露状态。
- 拒绝日记通常仍可支持安排、执行复盘、知识问答与自述帮助；源不足就收紧结论，不必扩权限。
- 允许数据 ≠ 允许写入；任何实际状态变更仍走已有确认链。

这进一步收窄 Phase D 的必要技术范围：先证明少量明确问题、少量允许材料、限定出站与拒绝后继续的价值；不从这些场景推导通用权限平台或 Agent Loop 必须立即建设。8 无本地记录需求，3 可本地直接事实回答，1 的固定规划与 12 的用户提供材料已可覆盖许多情况。真正需进一步检验的是 2、5、7 的范围理解和撤回一致性，不是更多读取本身。

## Implications For D0.4

仅列候选问题，不开始 D0.4：

1. 如何把 D0.1 场景、D0.2 证据边界和本模型合成最小 Phase D 产品能力及 eval baseline？哪些场景先保留现有普通 Chat / specialized workflows？
2. 哪个最小样本组合能同时覆盖零读取、单次事实、条件补证、本地允许但不发云端、单页材料与来源撤回？
3. 如何证明改善来自更少手动准备和更准确范围，而不是偷偷增加数据、更多等待或更长答案？
4. 哪些有限答案足以满足用户目标，哪些必须承认个人原因/历史事实无法证明？
5. 如何分别观察未经允许的本地读取、出站披露、派生复用和未确认写入，使任何一项违反都不能被平均质量掩盖？
6. 如何检验用户理解“近期复盘”“本地预览”“聚合”“重新生成”的实际含义，且不预先锁定 UI 方案？
7. 哪些后续范围可以完全使用独立片段和现有可信确认链完成，哪些能力缺口必须另获授权才研究？

## Questions For Later Implementation

以下仍是问题，不提出接口、存储或执行设计：

- 如何让实际本地读取/匹配范围与用户可理解范围一致，特别是完整对象读取、日期受限搜索和指定页材料？
- 如何在不持久化原始私人内容或隐藏推理的前提下，判断摘要/旧回答与被撤回来源的关系？来源不清时如何可靠停用？
- 如何防止出站前撤回、发送状态未知、晚到回答、重试快照与混合历史文本导致越界复用？
- 如何区分“允许保留历史”“不再用作证据”“不要再发送”和“删除记录”的体验，且保持现有回执与 Planning History 契约？
- 如何在 Provider 改变时保持去向理解，并如实说明应用能控制的后续请求与无法收回的既有披露？
- 如何验证本地可用但云端被拒的路径确实本机完成，不暗中调用服务，也不夸大本地分析能力？

以下是文档合成反例推演，**不是应用自动化测试、模型 eval 或真人验收**。

| 必验边界 | 合成输入 | 模型审查结果 |
| --- | --- | --- |
| Local allowed / disclosure denied | 只在本机搜索指定日记 | 命中原文、日期、数量均不自动出站；当前范围能力不足时不调用宽范围搜索。通过语义推演 |
| Bounded disclosure | 用户明确给当前 Provider 看独立一页草稿 | 仅指定页，不读取整 PDF、答案、同日日记；提取文本继承范围。通过 |
| Explicit sensitive denial | 不看日记，但允许看任务负荷 | 正文、标题、心情、日记派生摘要均排除；任务/自述仍可帮助。通过 |
| Derived after revocation | 旧回答混合了 diary summary 和 task facts | 不整段重发，不使用日记引出的优先级；可独立支持部分才继续，不能分离则停用。通过 |
| Sensitive match surface | 只准题面搜索；现有搜索含 answer/notes | 当前能力不符合，不能搜索后删字段冒充合规。通过 |
| User-provided attachment | 只准看第 3 页，却提供多页 PDF | 不能沿当前全页提取路径执行；需独立页/关键文本或有限答复。通过 |
| No local access | 克拉默法则知识问题 | 当前用户问题足够，不读取学习记录、不附无关旧本地派生内容。通过 |
| Action confirmation separate | “可以”回应“能看任务吗”，随后 AI 提出建任务 | 只同意读，没有创建确认；仍走候选校验/审阅/确认。通过 |
| Revoked before send | 已本地构建请求，随后拒绝 disclosure | 不发送快照及其派生摘要；允许的本地用途不自动丧失。通过 |
| Sent / uncertain | 发送后取消或超时，再撤回来源 | 不承诺收回字节；停止未来发送/证据复用，不采纳受影响晚到候选。通过 |
| Aggregate exception check | 禁发原始时刻但明确允许本机计算并发送某周合计 | 仅限定合计可披露；换成“不要再用 focus”则合计也停用。通过 |
| Historical action | 日记生成的建议已确认成任务，之后拒绝日记 | 不自动删任务/回执；任务中复制的私人事实不因持久化就允许再发。通过 |
