## New Tests Added

`tests/studyTaskParity.test.ts`

- Risk covered: SQLite and browser fallback task ordering drift.
- Risk covered: chapter deletion leaving ghost task references.
- Risk covered: cross-subject chapter attribution validation drift.
- Method: same fixture data in SQLite repositories and browser fallback refs, then compare complete query rows after controlling timestamps and project only the fields relevant to delete/nulling semantics.

`tests/databaseMigrations.test.ts`

- Risk covered: schema 4 to 5 migration adds a field without preserving old task data or FK semantics.
- Strengthened assertions: idempotent rerun, preserved old fields, index exists, FK points to `subject_chapters(id)` with `ON DELETE SET NULL`, `foreign_key_check` clean.

## Remaining Test Gaps

P2 candidate: subject list ordering parity.

- Evidence: SQLite orders subjects by `name`; fallback orders by `order`.
- Suggested test: same subject fixture in both paths should return the chosen canonical order.
- Recommended version: v1.13.2 or v1.14.0 depending on whether persisted custom subject order is introduced.

P3 candidate: non-task aggregate tie-breakers.

- Evidence: Pomodoro total-minute sorts and mistake created-time sorts lack secondary tie-breakers.
- Suggested test: fixtures with equal totals/timestamps stay stable across SQLite and fallback.
- Recommended version: v1.13.2.

P3 candidate: utility contract for `getNextTodayAction`.

- Evidence: utility chooses first matching task from input and does not sort internally.
- Suggested test: document ordered input requirement or add a wrapper-level test proving callers pass API-sorted tasks.
- Recommended version: v1.13.1 if docs-only, v1.13.2 if behavior changes.

Manual validation gap:

- Electron packaged UI was not manually run in this audit before docs were written.
- Suggested manual checks:
  1. Start Electron dev app.
  2. Create subject and detailed chapter.
  3. Add chapter to today from progress page.
  4. Confirm dashboard recommends chapter task.
  5. Start Pomodoro from recommended action.
  6. Finish focus and complete task + chapter.
  7. Delete a different chapter with a task and confirm the task survives without chapter badge.

## CI Alignment

Verified fact:

- CI uses Windows Node 22, `npm ci`, `npm rebuild better-sqlite3`, `npm run typecheck`, and `npx vitest run`.
- CI build verification runs `npm run build:electron` and `npx vite build`.
- Packaging verification rebuilds and verifies Electron native dependencies on Windows.

Risk:

- Local workstations can flip `better-sqlite3` ABI between Node and Electron. This occurred in this audit before running tests and was resolved with `npm.cmd rebuild better-sqlite3`.

Recommendation:

- Keep reporting whether tests ran against Node ABI or Electron ABI. If running tests after `npm run build`, rebuild for Node before rerunning Vitest.
