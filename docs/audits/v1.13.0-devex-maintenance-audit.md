# MindDiary v1.13.0 DevEx and Maintenance Audit

Status: audit of scripts, CI, release workflow, docs drift, and contributor runbook accuracy.

Schema status: schema unchanged.

## Scripts

Verified fact from `package.json`:

| Script | Purpose | Notes |
| --- | --- | --- |
| `build:electron` | TypeScript compile for Electron project | Used by CI and build |
| `build:resources` | Create icon/build resources | Used by CI/release packaging |
| `dev` | Build Electron then run Vite and Electron | PowerShell users should call `npm.cmd run dev` |
| `electron:dev` | Start Electron using built main process | Requires prior Electron build/Vite state |
| `postinstall` | `electron-builder install-app-deps` | Can compile native modules for Electron ABI |
| `rebuild:electron` | `electron-rebuild -f -w better-sqlite3` | Required before packaged Electron verification |
| `verify:electron-native` | Check native dependency loadability | Used by CI/release |
| `build` | Electron TS build, Vite, resources, Electron rebuild, native verify, electron-builder, packaged native verify | Full local build is heavy and mutates generated output |
| `test` | `vitest` | CI uses `npx vitest run` |
| `typecheck` | renderer and Electron TypeScript checks | CI gate |

DevEx risk:

- Running Electron rebuild can leave `better-sqlite3` compiled for Electron ABI. Running Node/Vitest after that can fail until `npm.cmd rebuild better-sqlite3` or `npm.cmd ci` rebuilds for Node. This happened during the audit before tests.

## CI Workflow

Verified fact:

- `.github/workflows/ci.yml` runs on pushes and PRs to `main`.
- Test job runs on Windows, Node 22, `npm ci`, `npm rebuild better-sqlite3`, `npm run typecheck`, `npx vitest run`, `npm run build:electron`, and `npx vite build`.
- Build-verification matrix runs Windows and macOS; Windows additionally rebuilds Electron native deps, verifies them, packages with `electron-builder --dir --win --x64 --publish never`, and verifies packaged native deps.

Risk:

- CI does not run Playwright e2e by default. This is acceptable for current scope but should be explicit in release readiness notes.

## Release Workflow

Verified fact:

- `.github/workflows/release.yml` runs on `v*` tags.
- It verifies tag matches `package.json` version and `RELEASE_NOTES.md` title.
- It builds Windows and macOS assets, verifies metadata, stages allowlisted assets, downloads artifacts into `release-artifacts`, validates combined manifest, and publishes via `softprops/action-gh-release`.

Pending confirmation:

- This audit inspected workflow source only. It did not re-run the release workflow or inspect current release asset hashes.

## Contributor Startup

Verified fact:

- README and scripts support standard Node/Electron setup with npm.
- For Windows in this environment, use `npm.cmd` to avoid shell shims.

Suggested contributor runbook:

1. `npm.cmd ci`
2. `npm.cmd rebuild better-sqlite3`
3. `npm.cmd run typecheck`
4. `npx.cmd vitest run`
5. `npm.cmd run build:electron`
6. `npx.cmd vite build`
7. For packaged Windows native verification: `npm.cmd run rebuild:electron`, `npm.cmd run verify:electron-native`, `npx.cmd electron-builder --dir --win --x64 --publish never`, `npm.cmd run verify:electron-native:packaged`.
