| File | Query area | Current use | Risk |

| `electron/database.ts#getTodayDashboard` | `taskRows` for same-day tasks | counts and task focus metrics, not user-facing order | Low |

| `electron/repositories/entriesRepository.ts#getDatesWithEntries` | calendar date/mood lookup | consumed as date-keyed calendar data | Low; output order is not the contract |

| various single-row lookups | by id/date/key | not list order | Low |

Conclusion: The task system's ORDER BY is sufficient. The remaining ordering risks are adjacent display lists and aggregate lists.

## Risk Classification

Confirmed issue: subject list ordering differs between Electron and browser fallback.

- Minimal fix: decide product order, then align one side. If preserving user-custom order is desired, SQLite needs an `order` field or separate explicit sort model; that is not a low-risk audit fix.
- Not fixing now: progress page subject order can differ between development/browser fallback and packaged Electron.
- Fixing wrong: changing Electron to name or fallback to name without product decision can surprise users who rely on fallback insertion order during development.
- Recommended version: v1.13.2 if treated as display consistency; v1.14.0 if adding persisted custom subject order.
- Acceptance: identical subject fixture returns identical ordered subject ids in SQLite and fallback tests.
- Rollback: revert focused ordering change and tests; no schema rollback if fallback-only.

Potential issue: non-task aggregate tie-breakers are incomplete.

- Minimal fix: add stable secondary keys in both SQLite and fallback aggregate sort paths.
- Not fixing now: equal totals/timestamps may show unstable list order in charts or mistake lists.
- Fixing wrong: changing order can alter snapshots and user expectations.
- Recommended version: v1.13.2.
- Acceptance: fixtures with equal totals/timestamps keep stable id/name/date order in both paths.
- Rollback: revert order clauses/comparators.

Non-issue: task ordering and chapter ordering.

- Evidence supports stable ordering because both paths use a domain order and id tie-breaker.
- New parity tests exercise same-fixture task ordering across SQLite and fallback.
