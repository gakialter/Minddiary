# MindDiary v1.13.0 SQLite Schema Inventory

Status: source-and-test-backed schema inventory for schema version 5.

Schema status: schema unchanged.

Primary evidence:

- `electron/databaseMigrations.ts` defines `CURRENT_SCHEMA_VERSION = 5`, `createCurrentSchema`, and migrations 1 through 5.
- `electron/database.ts` enables `PRAGMA foreign_keys = ON` before `runDatabaseMigrations`.
- `tests/databaseMigrations.test.ts` verifies schema version 5, registry continuity, idempotency, schema 4 to 5 migration, indexes, foreign keys, and backup restore compatibility.
- `tests/databaseLegacyMigrations.test.ts` verifies old fixture upgrade coverage up to current schema 5.
- `tests/databaseRepositories.test.ts` exercises repository behavior against SQLite tables.

## Inventory Risks

Confirmed issue:

- Documentation drift: some docs still state schema 4/v1.11-v1.12 planning while code and release notes are v1.13.0/schema 5. See `docs/audits/v1.13.0-devex-maintenance-audit.md`.

Potential issue:

- `subject_id` in `mistakes` and `pomodoro_sessions` has no `ON DELETE` action in SQLite, so `subjectsRepository.deleteSubject` manually nulls those rows before deleting a subject. This is currently intentional and covered by repository/fallback tests, but future delete paths must not bypass the repository.

Non-issue:

- The presence of `subject_chapters` in `createCurrentSchema` and migration 4 is not a duplicate schema bug. Migration 1 creates a current-compatible base schema for empty databases, while migration 4 handles older databases; `CREATE TABLE IF NOT EXISTS` keeps it idempotent.
